# 马拉松训练计划 Agent · 简历展示文档

## 一、现有项目诊断：为何难以在简历中展示

### 1. 功能与可访问性缺失
- 真实产品是本地 Flask 应用，需要 Python 环境、DeepSeek API Key 与依赖安装才能运行， recruiter 无法"点开即看"。
- 因成本顾虑未做公网部署，缺少可分享链接，面试中只能口头描述，缺少可验证证据。
- 旧静态 Demo 是"工具镜像"，读起来像内部后台，缺乏价值主张与叙事主线。

### 2. 交互与体验短板
- 没有突出核心差异点：**双模型（生成 + 反思）闭环**， recruiter 扫视 10 秒抓不住重点。
- 图表为裸 SVG，视觉层次弱，缺少"作品集感"与惊喜感。
- 多页工具式结构需要用户自己探索，不适合被动浏览的招聘场景。

### 3. 视觉与品牌问题
- 设计分析已指出：线上并存三套冲突配色令牌（LIME / AMBER / 提案 GREEN-TEAL-ORANGE），身份三重分裂。
- 配色研究推导的"暗底发光 + 克制专业"方向从未一致落地，整体观感不专业。
- 结论：功能强但"看不出强"，需要一层面向展示的包装层。

## 二、重新设计的交互 Demo（适合简历展示）

### 目标
用单文件、自包含、零依赖的静态页面，把"第一性原理 + 双模型闭环"讲清楚，且可点击体验。

### 页面结构
- 首屏 Hero：一句话价值主张 + 双模型 / 真实数据 / 闭环 三个核心标签。
- 核心能力：4 张卡片（双模型架构、真实数据感知、反思审查闭环、端到端可验证）。
- 功能演示（交互中心）：
  - ① 一键生成训练计划（带生成动画）
  - ② 反思审查前后对比（初版 vs 反思后，高亮改进点）
  - ③ 配速长期趋势图（悬停查看每月配速）
- 技术架构：工具使用 + 反思 的五节点流程图。
- 部署亮点：第一性原理部署决策，体现产品判断力。

### 交互与视觉
- 平滑滚动导航、生成动画、反思对比切换、图表悬停提示、滚动渐显。
- 统一深青 + 琥珀强调色，卡片化层次，响应式适配移动端。

## 三、如何查看与部署
- 本地：双击 `marathon-showcase/index.html` 即可在浏览器打开。

- 成本：¥0。

## 四、简历写法建议（呼应展示）
- 用"问题 → 第一性原理 → 决策 → 可验证交付"四段式，4–6 行呈现。

- 附：交互 Demo 链接 + 公开仓库，作为可验证证据。
