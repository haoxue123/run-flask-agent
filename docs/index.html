架构设计梳理

1项目目标：它解决什么核心问题

第一性原理 · Agent 的定义

Agent = 感知 → 推理 → 行动 → 反馈 的闭环系统。

目标用户：拥有运动手表（Garmin 等）的大众跑者，正备战半马 / 全马。

核心痛点：他们积累了真实跑步数据，却缺乏科学、安全、可执行的训练安排；私教贵、资料杂、通用 App 不看个人真实数据。

核心问题：把"真实数据"转化为"科学、安全、循序渐进的训练计划"，并随执行情况自我审查、动态调整。

差异化价值（3 点）

零

零 API 门槛

从手表导出 GPX/TCX/FIT 文件或手动填 JSON 即用，无需注册任何第三方 API。

思

自我反思

生成后由推理模型审查再输出，落地吴恩达"精心设计的 Agentic 工作流能让弱模型超越强模型"。

核

科学内核兜底

训练安全不能靠 LLM 自由发挥，单独建确定性内核做硬约束（防伤病）。

2全局分层架构（鸟瞰）

请求自上而下，响应自下而上。design/ 是设计稿"源真理"，showcase/ 是独立演示，二者均不参与运行时；运行时前端只有 templates/ + static/。

3前端架构：Flask MPA + SSR + 原生 JS 渐进增强

技术栈：Flask 模板（Jinja2）+ 原生 JS（IIFE + window 命名空间）+ 少量 CDN（Chart.js、Lucide）。无 React/Vue，无 webpack/vite，无 package.json。

运作逻辑（两段式）：① 首屏服务端渲染——base.html 为公共骨架，各页面 {% extends %}，后端注入画像/计划；② 交互靠原生 JS 增强——fetch 局部更新，教练对话用 SSE 流式。CSS 分三层：theme.css / design-system.css / execution.css。

选型理由（第一性原理）

选型决策理由
MPA 而非 SPA5 个功能页各自独立，跳转不频繁无需 SPA 路由/状态管理复杂度
SSR 而非前端渲染数据在后端（Python 画像/计划）Jinja2 注入是最短路径，省一次 API 往返
原生 JS 而非框架交互点有限（生成、打卡、对话）无构建链、零依赖，git clone 即跑，契合"教学演示"定位
SSE 而非 WebSocket对话只需服务端→客户端单向流SSE 更轻、基于 HTTP，实现成本最低

4后端架构（核心）：确定性内核 + LLM 双脑

技术栈：Flask 3 + OpenAI SDK（调 DeepSeek）+ ChromaDB + sentence-transformers + matplotlib，纯 Python 单进程。

架构模式

不是普通 CRUD 分层，而是 Agentic 编排 + 确定性科学内核并行 的"双脑"模式。

脑 A · 确定性科学内核（第 ④ 层）

physiology.py / plan_science.py / training_science.py：纯标准库、可复现，量化 TRIMP 训练负荷、ACWR 急慢性负荷比（伤病风险）、心率区间、配速换算。在闭环扮演两次护栏：事前 build_constraints 算出科学约束注入 prompt（llm_agent.py:578-591）；事后 enrich_plan 复核增强（llm_agent.py:644-661）。全程 try/except 可降级。

脑 B · LLM 双模型（第 ③ 层）

生成用 deepseek-chat（强制 JSON 结构化输出，解析"JSON 优先 + 正则兜底"）；反思用 deepseek-reasoner（带思维链）。底层 call_deepseek 封装指数退避重试、客户端单例。

Agent 编排三大高级能力（集中于 routes/coach.py）

能力实现设计巧思
状态机 + 意图分类workflow.py + classify_intent先关键词快速匹配（省 ~1s 延迟），未命中才调 LLM；意图驱动 chat/assess/advise/plan/track
工具使用skills.py + [TOOL:xxx]LLM 带工具标记 → 后端执行 → 结果回灌再生成，最多 2 轮循环
RAG 知识增强rag.py + ChromaDB按 ## 分块（600 字/100 字重叠）+ 多语言向量模型
长期记忆memory.py记住跑者偏好 + 对话历史（最近 10 轮），原子写入 JSON
流式响应SSE教练回复逐字推送，体验接近打字机

5数据与知识层（第 ⑤ 层）

  • 文件解析（parsers/ 策略模式）：GPX（gpxpy）/ TCX（标准库 xml）/ FIT（fitparse）/ CSV 四种格式。
  • 文件系统持久化：计划存 plan.json，记忆存 JSON，向量库持久化到 data/chroma_db/。
  • 部署含义：有状态应用，不能直接上云函数（临时磁盘丢数据）——对应轻量云服务器 + Docker Compose。

6选型理由一句话总结

最朴素的 Flask MPA 外壳（易跑易懂），包裹一个 确定性科学内核 + LLM 双模型 的双脑智能体（计划既智能又安全），完整实现"感知真实数据 → 推理生成 → 反思审查 → 动态调整"的 Agent 闭环。
