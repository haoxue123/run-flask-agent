# 面试展示步骤清单（两条路，照抄即可）

> 适用：纯面试展示（不是生产上线）。两条路跑的都是**真应用**（真调 DeepSeek + 真知识库），不是仿真页。
> 前置共识：展示不需要「用户数据跨周持久」，所以都不强制挂持久磁盘；知识库会在启动时自动重建（首屏慢几秒，无碍）。

---

## 路径 A：Railway 跑真应用（给面试官一个能点的真链接）

适合：想发个链接让面试官自己点开，看到真在调模型 + 真知识库。

### 准备（一次性）
1. 代码已提交到本地（commit `50e3ba1`，已含 `routes/tokens.py`、`relation_layer.py` 等必须模块）。**先推到 GitHub**——在你自己的终端、项目目录里运行（不要通过对话工具，那里没有你的 GitHub 写权限）：
   ```bash
   cd E:\AI\trae\agent
   git push origin main
   ```
   仓库：`haoxue123/run-flask-agent`。推上去后 Railway 才能拉到完整、可运行的代码。
   > 嫌 GitHub 麻烦？见下方「备选：Railway CLI 本地直传」，可完全不碰 GitHub。
2. 准备两个值：
   - `DEEPSEEK_API_KEY` = 你的 DeepSeek key
   - `SECRET_KEY` = 随便一段 ≥16 位随机串，例如 `sk-demo-7f3a9c2e1b8d4a6f`
3. 打开 railway.app，用 **GitHub 登录**注册。

### 部署（点几下 + 填几个值）
4. **New Project → Deploy from GitHub repo → 选 `run-flask-agent`**。
5. 部署方式选 **Dockerfile**；在 Settings 里确认：
   - Root Directory = `.`（仓库根）
   - Dockerfile Path = `deploy/Dockerfile`
6. 填环境变量（Variables 页面，逐个 Add）：
   - `SECRET_KEY` = 上面那段随机串
   - `DEEPSEEK_API_KEY` = 你的 key
   - `FLASK_DEBUG` = `false`
   - `PORT` = `5000`
7. **（可选，首屏更快）** Volumes → 新建一个卷，挂载到 `/app/data`。
   - 不挂也行：代价是每次重启知识库会重建、首屏慢几秒，展示无碍。
8. 等部署完成，Railway 会给一个 `xxx.railway.app` 域名 → 点开就是真应用。

### 验证
9. 打开链接 → 看到首页；点「AI 教练」聊一句「帮我定个全马训练计划」→ 收到真回答（证明是真模型 + 真知识库）。

### 卡住排查
- 打不开 / 启动失败：看 Railway 的 **Deploy Logs**，多半是 `SECRET_KEY` 没填（app 启动会硬拒）。
- 回答很泛、不像有知识库：RAG 降级了，不影响演示；想更稳就挂上 `/app/data` 卷。

### 备选：Railway CLI 本地直传（免 GitHub）
不想走 GitHub 的话，用 Railway 命令行直接把本机代码传上去：
1. 装 CLI（需先装 Node.js）：`npm i -g @railway/cli`
2. 项目目录里：`railway login` → 浏览器授权 GitHub/邮箱。
3. `railway init` → 新建项目（命名如 `run-flask-agent`）。
4. `railway up` → 直接上传当前目录（遵守 `.gitignore` / `.dockerignore`，未提交的改动也会一起传）。
5. 在 Railway 控制台把部署方式设为 **Dockerfile**，Dockerfile Path = `deploy/Dockerfile`；再填同样的 4 个环境变量（见步骤 6）。
6. 可选挂 `/app/data` 卷；部署完成拿到 `xxx.railway.app`。
> 好处：完全不碰 GitHub。代价：以后每次改代码要再跑一次 `railway up`（GitHub 方式会随 push 自动重新部署）。

## 路径 B：本机 Live 演示（零成本，屏幕共享）

适合：面试时直接跑你电脑上的程序、用腾讯会议 / 飞书共享屏幕，最稳、不花一分钱。

### 准备
1. 本机装了 **Python 3.11+**（终端输入 `python --version` 确认）。
2. 装依赖（一次性）：
   ```bash
   pip install -r requirements.txt
   ```
3. 在项目根目录建 `.env` 文件，内容：
   ```ini
   SECRET_KEY=sk-demo-7f3a9c2e1b8d4a6f
   DEEPSEEK_API_KEY=你的key
   ```

### 运行
4. 终端进入项目目录，运行：
   ```bash
   python app.py
   ```
5. 看到 `访问：http://127.0.0.1:5000` 即启动成功。
6. 浏览器打开 `http://127.0.0.1:5000` → 就是应用。
7. 共享屏幕，把浏览器窗口给面试官看，当场对话演示。

### 卡住排查
- 启动报错「缺少 SECRET_KEY」：确认第 3 步 `.env` 已填。
- 启动报缺模块：重跑 `pip install -r requirements.txt`。
- 知识库相关回答偏弱：本机若没装 `chromadb`，RAG 会自动降级，不影响主流程（教练仍能答，只是少了检索增强）。

## 怎么选
| 你的情况 | 选 |
|----------|----|
| 想「发链接、面试官自己点」 | 路径 A（Railway） |
| 想「零成本、最稳、当场演示」 | 路径 B（本机） |
| 想证明「真做出来了」（非仿真） | 两条都是真应用，任选 |

> 注：Vercel / Netlify 只适合放纯前端仿真页（不真调模型），不适合这两条真应用路径。
